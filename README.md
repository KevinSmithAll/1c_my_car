## ✨ О проекте

**«Моё Авто»** --- учебно-прикладная конфигурация на платформе
**1С:Предприятие**, предназначенная для ведения данных об автомобилях,
регистрации пробега, фиксации выполненных работ по техническому
обслуживанию и загрузки каталога деталей из JSON.

Проект развивается в сторону полноценной системы обслуживания
автомобиля. Ключевая цель --- объединить нормативы ТО и фактическую
историю эксплуатации, чтобы рассчитывать следующий срок обслуживания
**по пробегу и календарному времени**.

> \[!IMPORTANT\] Проект находится в разработке. README описывает текущие
> объекты, обнаруженные в выгрузке конфигурации, и целевое направление
> развития. Наличие метаданных не означает, что все пользовательские
> сценарии уже реализованы и протестированы. В частности, модуль расчёта
> ТО требует согласования с фактической структурой регистров и
> нормативов.

## 🧱 Архитектура

Конфигурация использует стандартные объекты метаданных 1С: справочники,
документы, перечисления, константы, регистры сведений, общий модуль и
обработку.

``` mermaid
flowchart TD
    A["Справочники<br/>Автомобили · Работы · Детали"] --> B["Документы"]
    B --> C["Изменить показания пробега"]
    B --> D["Произвести ТО"]
    C --> E["Регистр ПробегАвтомобиля"]
    D --> E
    D --> F["Регистр СделанныеТО"]
    A --> G["Общий модуль расчёта ТО"]
    E --> G
    F --> G
    H["JSON-файл"] --> I["Обработка ЗагрузкаДеталей"]
    I --> J["Номенклатура деталей"]
```

### Основные объекты конфигурации

#### Справочники

-   **`Автомобили`** --- сведения об автомобилях; в текущем коде
    используется начальный пробег.
-   **`РаботыПоАвто`** --- каталог работ, связанных с обслуживанием
    автомобиля.
-   **`РегламентныеОперации`** --- справочник регламентных операций.
-   **`НоменклатураДеталей`** --- карточки деталей, включая связь с
    автомобилем и данные, используемые при импорте.

#### Документы

-   **`ИзменитьПоказанияПробега`** --- регистрирует показание одометра;
    при проведении формирует движение в `ПробегАвтомобиля`.
-   **`ПроизвестиТО`** --- фиксирует автомобиль, текущий пробег и
    выполненные работы; формирует движения по пробегу и выполненным ТО.

#### Регистры сведений

-   **`ПробегАвтомобиля`** --- история зарегистрированных показаний
    пробега.
-   **`СделанныеТО`** --- сведения о выполненных работах, автомобиле,
    дате и пробеге.
-   **`НачальныеПараметрыТО`** --- регистр начальных параметров
    обслуживания; его точная роль должна быть закреплена в целевой
    модели расчёта.

#### Прочие объекты

-   **`ОбщийМодуль`** --- содержит функцию `ПолучитьДанныеТО()`,
    предназначенную для получения данных по обслуживанию автомобиля.
-   **`ЗагрузкаДеталей`** --- обработка импорта каталога из JSON.
-   **`ЕдиницыИзмерения`** --- перечисление единиц измерения.
-   **`Автомобиль`** --- константа конфигурации.

## 🔄 Как устроен процесс обслуживания

Целевой пользовательский сценарий:

1.  Добавить автомобиль и указать начальные данные.
2.  Зафиксировать актуальный пробег документом.
3.  Настроить регламентные работы и интервалы обслуживания.
4.  При выполнении ТО создать документ `ПроизвестиТО`, указать дату,
    пробег и выполненные работы.
5.  Рассчитать для каждой работы следующий срок по пробегу и по времени.
6.  Вывести список работ, которые скоро потребуются или уже просрочены.

### Принцип расчёта

Для регламентов с контролем по пробегу:

`Следующий пробег = пробег последнего выполнения + интервал пробега`

Для регламентов с календарным контролем:

`Следующая дата = дата последнего выполнения + календарный интервал`

Если одновременно включены оба критерия, рекомендуемое правило --- ТО
наступает при срабатывании **любого** критерия, то есть при достижении
того срока, который наступит раньше. Это правило следует закрепить в
реализации и тестах.

> \[!NOTE\] Для автомобиля без истории обслуживания требуется определить
> начальную точку отсчёта: дата и пробег ввода в эксплуатацию, дата
> назначения регламента либо явно введённые начальные параметры. Этот
> сценарий должен быть согласован до реализации окончательного
> алгоритма.

## 📦 Импорт каталога из JSON

Обработка **`ЗагрузкаДеталей`** предлагает выбрать JSON-файл и передать
его на сервер для разбора и импорта.

По текущей реализации ожидается, что корневой элемент JSON --- **массив
объектов**. В записи используются поля:

  -----------------------------------------------------------------------
  Поле                                Назначение
  ----------------------------------- -----------------------------------
  `Наименование`                      Наименование детали; обязательное
                                      поле

  `Автомобиль`                        Наименование автомобиля, который
                                      должен существовать в справочнике

  `Комментарий`                       Дополнительная информация о детали
  -----------------------------------------------------------------------

В коде импорта также предусмотрена работа с данными о
производителях/брендах и ценах. Точный состав обязательных и
дополнительных полей нужно сверять с полной реализацией обработчика и
реальным источником данных.

### Пример минимального JSON

``` json
[
  {
    "Наименование": "Масляный фильтр",
    "Автомобиль": "Пример автомобиля",
    "Комментарий": "Пример записи каталога"
  },
  {
    "Наименование": "Воздушный фильтр",
    "Автомобиль": "Пример автомобиля",
    "Комментарий": "Проверить применимость перед использованием"
  }
]
```

**Перед импортом:**

-   убедитесь, что указанные автомобили уже заведены в справочнике;
-   используйте UTF-8;
-   проверьте корректность JSON и обязательные поля;
-   сначала протестируйте импорт на копии информационной базы;
-   после импорта проверьте созданные карточки, цены и отсутствие
    дублей.

## 🚀 Запуск и работа с конфигурацией

Репозиторий содержит выгрузку метаданных 1С в XML и исходные модули BSL.
Это не готовый установщик и не файл информационной базы.

Общий сценарий работы:

1.  Установить совместимую версию **1С:Предприятия / Конфигуратора**.
2.  Создать тестовую информационную базу.
3.  Загрузить конфигурацию из файлов выгрузки средствами Конфигуратора
    либо перенести объекты в существующий проект подходящим для
    используемой версии способом.
4.  Проверить структуру метаданных и ссылки в модулях.
5.  Выполнить проверку конфигурации, обновить конфигурацию базы данных и
    запустить приложение в тестовом режиме.
6.  Проверить проведение документов, движения регистров и импорт JSON на
    тестовых данных.

> \[!WARNING\] Не загружайте экспериментальную конфигурацию
> непосредственно в рабочую базу без резервной копии. Перед
> использованием проверьте права, проведение и отмену проведения
> документов, корректность движений и поведение при ошибках.

## 🧪 Контрольный список тестирования

Перед выпуском версии проверьте следующие сценарии:

-   [ ] Новый автомобиль без истории ТО.
-   [ ] Автомобиль с уже существующей историей пробега.
-   [ ] Выполнение одной работы из нескольких назначенных.
-   [ ] Просрочка по времени при ещё не достигнутом пробеге.
-   [ ] Просрочка по пробегу до наступления календарной даты.
-   [ ] Работа без одного из двух критериев контроля.
-   [ ] Попытка провести документ с меньшим пробегом.
-   [ ] Повторное проведение и отмена проведения документа ТО.
-   [ ] Повторный импорт того же JSON.
-   [ ] JSON с отсутствующими полями, неизвестным автомобилем и неверным
    форматом.

## 🛠️ Технологии

-   **Платформа:** 1С:Предприятие, управляемое приложение.
-   **Язык бизнес-логики:** встроенный язык 1С (BSL).
-   **Формат выгрузки метаданных:** XML.
-   **Формат обмена каталогом:** JSON.
-   **Архитектурные объекты:** справочники, документы, регистры
    сведений, общий модуль, обработка данных.

Точная версия платформы, требования к режиму совместимости и минимальная
поддерживаемая версия должны быть зафиксированы в проекте отдельно. В
XML конфигурации указан режим совместимости `Version8_3_27`; это не
заменяет проверку всей конфигурации на целевой платформе.
